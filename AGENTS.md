# Правила для AI-агентов

Перед работой прочитай README.md, MASTER_PROMPT_RU.md и docs/PROGRESS.md, затем handoff и полную спецификацию активного milestone.

## Обязательные ограничения
- Целевая версия Unity — 6000.6.10f1.
- Игра строго 2D.
- Организм и его анатомия процедурные; не подменяй морфологию заменой спрайтов или готовых животных.
- Обучение в течение жизни, изменение морфологии и наследование поколений — разные процессы.
- Текущая концепция Evolution сосредоточена на одном организме, который учится и меняется в течение собственной жизни. Не навязывай обязательные поколения, размножение, смерть или перерождение.
- Среда только природная: рельеф, вода, растительность, погода и другие естественные факторы. Не добавляй искусственные ловушки и придуманные испытательные полосы.
- Не начинай системы, не относящиеся к текущему milestone.
- PEE и другие репозитории не трогать.

## Порядок чтения и источник истины
1. Прочитай README.md, MASTER_PROMPT_RU.md и docs/PROGRESS.md.
2. Прочитай docs/DECISIONS.md и handoff активного milestone.
3. Полностью прочитай спецификацию активного milestone. Для EV-CP2 это docs/EV_CP2_SPEC.md.
4. Спецификация активного milestone уточняет и, где явно указано, supersedes исторические цели ранних прототипов в MASTER_PROMPT_RU.md. Не реализуй устаревший milestone вместо текущего.
5. Открой .agents/skills/SKILL_INDEX.md.
6. Загрузи только 1–3 профильных навыка из .agents/skills/<skill-name>/SKILL.md.
7. Не читай целиком исходные репозитории навыков без конкретной причины. Активные копии лежат непосредственно в .agents/skills/.
8. Не загружай все навыки одновременно: это расходует контекст и снижает точность.

## Версия Unity — критическое правило
- Целевая версия проекта: Unity 6000.6.10f1 (Unity 6.6).
- Некоторые сторонние навыки написаны под Unity 6.3 (6000.3). Используй их как общие ориентиры, но не считай API-инструкции гарантированно совместимыми.
- Перед использованием спорного API сверяйся с фактическими пакетами проекта и документацией/кодом установленной версии.
- Не обновляй и не понижай Unity и пакеты ради соответствия skill-файлу.
- Проект строго 2D: 3D-части навыков игнорируй.

## Качество
- Проектируй проверяемые, детерминированные алгоритмы и воспроизводимые тесты.
- Разделяй физическую реализацию, визуализацию и управляющую логику.
- Для динамической геометрии проверяй топологию, winding, индексы, вырожденность и самопересечения там, где применимо.
- Визуальная и физическая формы должны оставаться согласованными.
- Обучение не должно зависеть от FPS.
- Не добавляй пакеты без необходимости.
- Не заявляй о запуске/тестировании в Unity без фактической проверки.

## Git
- Сначала изучи актуальное состояние репозитория и пользовательские изменения.
- Не используй force push и не переписывай историю.
- Делай тематические коммиты.
- Обновляй docs/PROGRESS.md после каждой значимой работы и docs/DECISIONS.md при принятии решений.
- Kickoff handoff/spec для нового milestone можно создавать по прямому запросу пользователя. Не создавай промежуточные handoff-документы без необходимости.
- Никогда не меняй и не удаляй файлы вне текущего проекта.

## Навыки
- Unity C# / компоненты: unity-csharp-scripting.
- 2D физика / Collider2D: unity-physics.
- Стабильность симуляции / timestep: physics-tuning вместе с unity-physics.
- Данные и настройки: unity-scriptableobjects, только если нужны data assets.
- Поведение и принятие решений: сначала game-ai; BT/Utility — только если обоснованы, через ai-behavior-trees-utility-ai.
- Генерация окружения: procedural-gen. Не применять как готовое решение для непрерывной морфологии существа.
- Код-ревью качества: antislop-code.

## Impeccable
Применяй подключённый навык только для реальных UX/UI задач. Он не заменяет Unity, C#, геометрию и физику.
