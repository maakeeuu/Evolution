# EV-CP2 — проверка первого физического среза

Версия Editor **6000.6.10f1**, текущий Built-in pipeline. EV-CP1 сохранён.
**Агент не запускал Unity, не компилировал Unity API/шейдер и не выполнял PlayMode-тесты.**
Срез реализует физическую цепь и мышечные приводы в исходниках; нативный результат требует проверки ниже.

## Что должно быть в первом срезе

- Канонический код: `Evolution_Source/Articulated/{Core,Unity}`.
- Побайтовое runtime-зеркало: `Assets/Evolution/EVCP2/{Core,Unity}`.
- Две новые сборки Evolution.Articulated.Core / Evolution.Articulated.Unity.
  Core использует только чистые помощники EV-CP1 (Point2, finite/contour validation/fan),
  не радиальную морфологию и не старый motor. Новый Unity-код не зависит от старых MonoBehaviour.
- Детерминированная цепь 2..8 сегментов с небольшим пропорциональным taper, без seed/готового животного.
  В демонстрации четыре сегмента, три HingeJoint2D, шесть мышц.
- Каждый сегмент — отдельный Dynamic Rigidbody2D с гравитацией и PolygonCollider2D.
  Физические объекты — siblings; родительская топология задаётся данными/connectedBody,
  а не вложенными движущимися Transform. Соседние перекрывающиеся части не сталкиваются;
  несоседние self-contact остаются включёнными. Суставные motor отключены, limits ±40°.
- Парные мышцы имеют точки крепления по обе стороны шарнира. Activation плавно сокращает
  preferred length. Pull-only spring/damper демонстрации ограничен 60 N, одинаковая и противоположная сила
  применяется в двух точках через AddForceAtPosition в FixedUpdate; никаких команд скорости корня.
- Отдельный MuscleWaveDriver2D выдаёт открытое синусоидальное возбуждение.
  Это инструмент проверки привода, **не обучение и не доказательство освоенной локомоции**.
- Первая оболочка — непрозрачное объединение перекрывающихся капсульных участков;
  каждый видимый patch копирует точные float-вершины своего PolygonCollider2D.
  Все части используют один существующий Resources shader EvolutionVector2D (Built-in pass Always).
  Не добавляйте вторую копию с тем же Resources-ключом.
- Диагностические кости, точки шарниров и мышцы видимы отдельно. Они не являются коллайдерами.
  Материал/меши/PhysicsMaterial создаются только в runtime и освобождаются владельцами.

## Быстрый запуск — новая сцена, не поверх EV-CP1

1. Получите main, откройте корень репозитория строго в Unity 6000.6.10f1.
2. Дождитесь импорта. Сохраните созданные Editor настоящие .meta; существующие не удаляйте.
3. Проверьте Console: отсутствие C# binding/shader/missing reference ошибок — обязательный gate.
4. Создайте Empty Scene без лишних камер. Создайте пустой `EVCP2 Bootstrap`, identity Transform.
5. Добавьте **ArticulatedDemo2D**. Сохраните сцену через Editor как
   `Assets/Evolution/EVCP2/Scenes/EVCP2_Articulated.unity`; GUID вручную не создавать.
6. Physics2D Simulation Mode = Fixed Update, Gravity Y = -9.81, Default↔Default collision включена,
   Time Scale = 1, Fixed Timestep = 0.02. Агент эти глобальные настройки не менял.
7. Нажмите Play. Runtime-root содержит камеру, один профиль почвы и Articulated organism.
   Организм создаёт четыре физических сегмента/три шарнира/шесть мышц, падает на грунт.
   Ожидается сгибание под возбуждением мышц. Не считать успехом одно лишь падение или движение линий.
8. На ArticulatedOrganismView2D переключите Show Shell / Show Skeleton / Show Muscles,
   чтобы осмотреть физический скелет и затем покрытие. Цвета временные.

## Раздельные физические проверки

- [ ] **Passive:** отключите MuscleWaveDriver2D, выключите Muscles Enabled на организме.
      Все шесть сил должны стать нулевыми; тело свободно падает/лежит, суставы не распадаются.
      Простое отключение driver очищает команды, но passive spring tension может сохраниться;
      для полного удаления приводных сил используется именно Muscles Enabled = false.
- [ ] **Activation:** включите мышцы/driver. Проверьте изменение реального jointAngle и сегментов,
      а не только цвет/толщину линий. GetActivation/GetTension доступны из debugger; tension 0..60 N.
- [ ] **Antagonists:** отключите driver. Из debugger/временного локального harness подайте
      SetActivationCommand(0,1), остальные 0, затем ClearCommands и команду на мышцу 1.
      Соседние сегменты должны сгибаться в противоположные стороны.
- [ ] **No fake propulsion:** в отдельной копии сцены без почвы задайте gravityScale=0,
      linearDamping=0, angularDamping=0 всем сегментам. Мышцы меняют относительные углы,
      но не должны разгонять общий центр масс при отсутствии внешних сил/контакта.
- [ ] **Surface:** падение/контакт, трение и взаимодействие с природным склоном устойчивы
      60 секунд, нет туннелирования/взрыва/заметного растяжения joint anchors.
      Измерьте максимальный разрыв anchors; ориентир первого gate <0.02 world units.
- [ ] **Limits:** jointAngle остаётся около ±40° с допустимой погрешностью solver; useMotor=false.
- [ ] **Shell:** при сгибании покрытие не рвётся на шарнирах; нет лишнего прозрачного шва.
      Каждый patch и его collider совпадают. Кости/мышцы поверх — debug, не внешняя форма.
- [ ] **Lifecycle:** отключение/включение organism/Bootstrap не создаёт новые тела/ресурсы;
      root приостанавливается. Удаление organism/view/Bootstrap не оставляет невидимых collider,
      висящих muscle lines и утечек собственных native Mesh/Material/PhysicsMaterial.
- [ ] **Error:** некорректный начальный scale или отсутствующий shader приводит к одному
      сообщению и отключению/удалению частичной конструкции, не к невидимой физике.
- [ ] **Regression:** предыдущая EV-CP1 сцена по-прежнему импортируется и отображается.
- [ ] **FPS/Profiler:** сравните 30/144 FPS при одном fixed timestep; измерьте native solver,
      contacts/allocations. Core/driver детерминированы, нативная физика не гарантирует
      побитового совпадения между платформами. Не двигайте host Transform во время симуляции.

## Ограничения и незавершённые требования EV-CP2

- Нативная компиляция/физика/рендер/тесты ещё не подтверждены. Наличие силы в коде не доказывает
  успешную локомоцию; скорость/направление перемещения по поверхности не гарантированы.
- Первая оболочка непрерывна по покрытию только при корректно сведённых anchors.
  Это **не единый сваренный manifold mesh и не гладкая глобальная деформируемая кожа**:
  на сгибах возможны изменения кривизны; нет поддержки arbitrary branches/global contour union.
  Это промежуточный envelope, не выполнение всей задачи оболочки.
- Длины/радиусы/топология фиксируются при Start. Изменение serialized anatomy во время Play
  не перестраивает её. Непрерывный рост/ветвление/удаление структур ещё не реализованы;
  не подменять их мгновенным rebuild или интерполяцией, названной адаптацией.
- Нет обучения, балансирующего feedback-controller, биологических энергозатрат, органов,
  weather/water/биома и поколений. Sensor seam сейчас — реальные joint/body/contact значения.
- При удалении/отключении отдельного физического сегмента/сустава организм fail-closed останавливается;
  динамическая хирургия не поддерживается. Неравномерный scale/3D rotation не поддерживаются.
- Отключение view скрывает графику, но не предназначено для остановки физики: отключайте organism/Bootstrap.
- Шейдер переиспользуется из EV-CP1 Resources; удалять тот ресурс нельзя. SRP не валидирован.

Пришлите commit SHA, первый полный Console error (если есть), короткое видео passive/active,
значения jointAngle/anchor gap и результат чек-листа. Следующий gate — нативная проверка
этого среза, затем стабилизация контактов и развитие настоящей гладкой оболочки.

## Checkpoint A: исправление силового бюджета и обязательный native gate

Пользователь проверил d1ce36b: активация видна, **сгибания на опоре нет**. Это неуспешная локальная проверка.
В исходниках подтверждён недостаточный бюджет привода: старый максимальный момент в нейтральном положении меньше момента веса одного крайнего сегмента. Демонстрационный профиль теперь 60 N, 600 N/m, 6 Ns/m; общие Core defaults сохранены. Единственность причины и результат исправления в Unity НЕ подтверждены.

На организме включите Capture Diagnostics у ArticulationDiagnostics2D. Snapshot обновляется 4 раза в реальную секунду, HUD отсутствует. Он показывает command/activation/tension (N), L/target (m), rate (m/s), фактическую величину силы, world attachment points; по суставам angle/speed, limits/motor/enabled/active, обе world anchors и gap; по телам p/v/omega/mass/constraints/sleep; COM, active counts, PhysicsSteps, timeScale, fixedDt и simulationMode. Сила — последний опубликованный batch, тело/сустав — фактическое состояние при чтении.

Изолированная проверка: отдельная Empty Scene, один объект SingleJointProbe2D, identity Transform, без других объектов/поверхностей/сил. Это временный путь до Editor builder следующего checkpoint. Никаких manual gravity/velocity edits не нужно. Play запускает A/B/D/C/D (~6 игровых секунд); результат доступен в Inspector Result и Console.
- A: обе команды 0, drift angle <0.1°, v<.001 m/s, omega<.1°/s.
- B/C: отдельные свежие экземпляры для каждого антагониста; tension>.1 N и фактическая peak joint deflection >5°, противоположные знаки.
- D: команды сняты, activation<.001 через 1 игровую секунду. Не требуем возврата в исходную позу: упругость и инерция остаются физическими.
- В течение теста: нет контактов, motors=false, COM drift<.002 m, |total momentum|<.002 kg m/s, anchor gap<.01 m. Эти малые абсолютные допуски для ~1.7 m / .67 kg fixture — начальный численный gate, не утверждение измеренной точности solver.
- FAIL: приложите полный Result, Snapshot и Console. Не принимайте изменение цвета или positive tension за PASS. ABORTED при disable требует нового Play.

Только после PASS изолированного режима проверяйте поверхность 60 игровых секунд: падение, contact, max anchor gap<.02 m, limits ±40° с solver tolerance, отсутствие разлёта/сильного дрожания. Отдельно passive и wave drive. Локомоция не обещана. Автоматические PlayMode cases лишь подготовлены, **не запускались**.

## Checkpoint C: скорость и пауза

В новой demo-сцене builder добавляет один независимый SimulationTimeControl2D рядом с ArticulatedDemo2D на bootstrap. Панель не является RequireComponent-зависимостью: её можно удалить, не удаляя физическую демонстрацию; время будет освобождено. Если сохранённая старая сцена уже существует без него, меню Create/Open предлагает добавить только недостающий контроллер через Undo. Нажмите Add и Ctrl+S один раз. Другие объекты/настройки не заменяются. На isolated probe контроллер намеренно не добавляется: native A/B/C/D проверяйте на 1x до поверхности/ускорения.

Панель сверху справа: **II / 1× / 2× / 5× / 20×**; выбранный режим выделен. II и Space переключают паузу/последний непаузный режим. Сфокусируйте Game View: **1→1×, 2→2×, 3→5×, 4→20×** (также NumPad). Модификаторы Ctrl/Alt/Cmd игнорируются; старый input adapter EV-CP1 в новой сцене отсутствует. У Show Controls и Keyboard Shortcuts отдельные переключатели; скрытие панели не останавливает менеджер. Для освобождения владения временем отключите/удалите компонент.

Контроллер сохраняет предыдущее значение timeScale на каждом включении и начинает с 1×. Pause задаёт 0; Update/OnGUI/реальные часы работают и на паузе. Disable/Destroy восстанавливает прежнее значение только при сохранённом владении; повторный Destroy после Disable не пишет второй раз. При внешнем изменении timeScale контроллер прекращает владение, не перетягивает его и не восстанавливает поверх чужого значения. Нельзя обнаружить, что другой менеджер записал точно такое же значение — нужен общий протокол между менеджерами. Дубликат контроллера отключается с предупреждением.

`Time.fixedDeltaTime` **не изменяется вообще**, ожидается .02 игровой секунды. Если в проекте иное значение — предупреждение, но не скрытая правка. `maximumDeltaTime`/проектные настройки тоже не меняются. При 20× ожидаемая нагрузка — 1000 физических шагов за реальную секунду. Панель отдельно показывает выбранный режим, фактически продвинутые FixedUpdate игровые секунды / реальные секунды и steps/s (окно .5 s). После переключения дайте окну обновиться. Если measured значительно ниже 20× — CPU или Maximum Allowed Timestep ограничивают throughput; надпись 20× не является доказательством фактических 20×.
